### Step 2: Verify JwtAuthenticationFilter Behavior ✅ COMPLETE

**File:** `Backend/src/main/java/com/helpinminutes/api/security/JwtAuthenticationFilter.java`

**Verification Result:** ✅ CORRECT - JwtAuthenticationFilter properly handles invalid tokens

The JwtAuthenticationFilter correctly implements JWT validation:

```java
@Override
protected void doFilterInternal(
    HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
    throws ServletException, IOException {

  String auth = request.getHeader(HttpHeaders.AUTHORIZATION);
  if (auth != null && auth.startsWith("Bearer ")) {
    String token = auth.substring("Bearer ".length()).trim();
    try {
      UserPrincipal principal = jwtService.parseAccessToken(token);
      var authorities = List.of(new SimpleGrantedAuthority("ROLE_" + principal.role().name()));
      var authentication = new UsernamePasswordAuthenticationToken(principal, null, authorities);
      SecurityContextHolder.getContext().setAuthentication(authentication);
    } catch (Exception ignored) {
      // Invalid tokens are treated as unauthenticated.
    }
  }

  filterChain.doFilter(request, response);
}
```

**What this does:**
- Checks for Authorization header with "Bearer " prefix
- Attempts to parse and validate the JWT token
- **Catches all exceptions** (invalid signature, expiration, format issues, etc.)
- Does NOT set authentication for invalid tokens
- Passes request to next filter without authentication
- Spring Security then applies the authenticationEntryPoint for unauthenticated requests

**Key Behavior:** 
- Invalid tokens are silently ignored (treated as unauthenticated)
- No 403 Forbidden response is generated by this filter
- The `authenticationEntryPoint` handles the response with 401
